## Toast / Popover / Popconfirm（40 组件 / 80 测试）

**Toast**：模块级队列（`composables/toast.ts`）+ `<MochiToastHost />` + `useToast()`。
动效的关键三处：
1. 离场卡片设 `position: absolute`——否则它一消失，下面的通知会"跳"一下补位
2. `TransitionGroup` 的 `move-class` 让剩余通知平滑上移
3. 进度条用 CSS 动画 + `animation-play-state` 暂停/续播；JS 定时器同步扣减剩余时间，两条时间线一致

**Popover**：锚点定位，下方放不下自动翻上；`role="dialog"` + 点击外部/Esc 关闭。
**Popconfirm**：基于 Popover，`tone="danger"` 只换底色不改尺寸（避免弹层跳动）。

**踩坑（重要）**：Popover 的包装层和用户的按钮都绑了 `@click="toggle"`，冒泡触发两次 → 开了立刻关。
修法：**点击由包装层统一处理**，slot 只给 `{ open, attrs }`，不再给 `toggle`。文档里写明了这条。

## Table + Upload（42 组件 / 83 测试，P0 清空）

**Table**：真 `<table>`，列定义 + 三态排序（升序→降序→取消）+ `sort-change` + `aria-sort`；
`cell-{key}` 作用域插槽自定义单元格。排序箭头靠 `rotate: 180deg` 翻转，未排序时透明。

**Upload**：只做选择与列表，**不做上传**（鉴权/并发/重试每个项目都不一样，塞进组件只会变成又一个要配置的壳）。
拖入时整块 `scale(1.01)` 吸住；文件行离场绝对定位 + `move` 过渡补位（同 Toast 手法）。

**踩坑**：Select 的箭头在关闭态也朝上。原因是 `:data-open="false"` 会渲染成 `data-open="false"`，
而 CSS 写的 `[data-open]` 是"属性存在即匹配"。改成 `[data-open='true']` 才对。
**规律：布尔型 data 属性要么用 `x || undefined` 不渲染，要么 CSS 里按值匹配，绝不能只写属性名。**

## Dropdown / CountUp / Result / Space / Link / Text（48 组件 / 88 测试）

- **Dropdown** 挂在 Popover 上：给 Popover 加了 `panelRole` 参数（`dialog` / `menu`），
  菜单项 `role=menuitem`，↑↓ 移动焦点，按索引错峰 24ms 上浮
- **useCountUp 组合式函数**：rAF + easeOutCubic + `Intl.NumberFormat`，
  Statistic 与 CountUp 共用一份实现（数字滚动只有一处代码）
- **Result** 勾/叉用 `stroke-dashoffset` 画出来，延迟 120ms 等外圈弹到位
- **Link** 下划线用 `background-size` 从 0 拉满（不触发重排）
- **Text** 用 `as` 控制标签，避免为每个语义再开一个组件

## 徽标 bug + Carousel / TimePicker（53 组件 / 96 测试）

**徽标角标不下沉**：`Badge` 的角标是相对包装层绝对定位的兄弟节点，而按钮按下时位移发生在

  Collapse summary 补 margin:0、Table root 补 display:table/margin:0/overflow:visible、
  th/td 补 border:0、td 补 font-size:inherit、tr 补 background/border-top:0、
  新增 tr:nth-child(2n) 透明底（压 vp 斑马纹）、Link 补 `.root.root::after{content:none}`。
  10 个列表模块加 `> * { margin-top: 0 }` 对抗 li+li。
- **坑**：reduced-motion 块里的缩进同名规则也要一起双类（否则压不住主规则的过渡）。
- **验证**：计算样式逐项复测（Panel h3 18px/800/0 ✓、table display:table/边框 0 ✓、
  tr 透明 ✓、Link 颜色/无下划线/无外链图标 ✓）；33 页截图级检查通过；
  文档站原生表格（props 表）不受影响——custom.css 的桥接只管文档自己的表格。
- 定理级结论：**组件的每个元素样式都必须由组件自己的类选择器声明，
  "依赖宿主没有样式"的假设在文档站这类富样式宿主里必然翻车。**

这轮抓到的**真 bug**（跨组件的存量问题，不是新组件引入）：
- **Badge 的裸属性选择器全局泄漏**：`[data-tone='primary'] {...}` 在 CSS Modules 里不哈希，
  是全局规则——命中页面上任何带 data-tone 的元素。ProgressRing 恰好是第一个
  「根元素带 data-tone 且自身无背景声明」的组件，被染成实心色块才暴露。
  修法：限定为 `.pill[data-tone=…]`。教训：**CSS Modules 只哈希类名，
  属性/元素选择器都是全局的**——和上一轮 vp-doc 污染同根同源。
- ProgressRing 的 value 顺手改成 defineModel（v-model 和 :value 都能用）。

**测试环境两个新坑**：
1. VTU `mount()` 默认挂到**游离 div**——jsdom 的 `.focus()` 对未挂载节点无效，
   断言焦点要 `attachTo: document.body`（+ unmount 清理）。
2. 模板内联函数 ref（`:ref="(el) => ..."`）在 v-for + 组合式写法下不可靠，
   需要元素定位时用**容器 ref + querySelectorAll** 最稳。

**浏览器验证的一个教训**：查组件状态用 `document.querySelector('.demo')` 会命中
页面第一个 demo 容器——多 demo 页面必须从目标元素 `closest('.demo')` 往外找，
否则永远读到别人家的状态（这轮"标签加不上"排查半天就是这个）。

当前：71 组件 / 120 测试 / 文档 34 页。IAB 的 cua.keypress 在后台标签页不派发键盘，
验证键盘行为优先用 evaluate 派发标准事件。
